# 프로젝트 요구사항

## 1. 목표

React와 TypeScript를 사용해 한국어와 영어를 지원하는 반응형 컨택트 폼을 구현한다.

사용자는 연락처와 문의 내용을 입력하고 제출할 수 있다. 제출 데이터는 서버로 전송하거나 저장하지 않으며, 클라이언트에서 검증을 통과하면 제출 완료 화면을 표시한다.

핵심 구현 범위는 다음과 같다.

- React Hook Form을 이용한 폼 데이터 검증
- Radix 기반의 헤드리스 UI로 커스텀 폼 디자인 구현
- CSS Modules를 이용한 컴포넌트 스타일링
- TypeScript 데이터 모델 정의
- `react-i18next`를 이용한 한국어·영어 지원
- UI 테스트 자동화

## 2. 폼 검증

React Hook Form을 사용해 폼 데이터를 검증한다. 검증 흐름은 다음과 같다.

- 사용자가 입력하는 동안에는 검증하지 않고 제출 버튼을 눌렀을 때 전체 폼을 검증한다
- 최초 제출에 실패한 이후에도 입력 중에는 재검증하지 않고, 다시 제출했을 때 전체 폼을 검증한다
- 오류가 있는 필드는 오류 상태와 메시지를 표시하고 가장 먼저 발견된 오류 필드로 포커스를 이동한다
- 오류가 하나라도 발견되면 제출 성공 화면으로 이동하지 않는다
- 검증에 성공하면 제출 성공 화면으로 전환한다
- 성공 화면에서 다시 작성하기 버튼을 누르면 폼 데이터와 오류를 초기화하고 입력 화면으로 돌아간다

상세 검증 규칙은 다음과 같다.

| 입력&nbsp;항목 | 허용 값                        | 필수 여부 | 검증 규칙                                                           | 검증 실패 메시지                                                     |
| -------------- | ------------------------------ | --------- | ------------------------------------------------------------------- | -------------------------------------------------------------------- |
| 이름           | Unicode 문자열                 | 필수      | 앞뒤 공백 제거 후 1~50자                                            | `"이름을 입력하세요"` / `"이름은 50자를 초과할 수 없습니다"`         |
| 이메일         | 이메일 문자열                  | 필수      | 빈 값이 아니며 일반적인 이메일 형식이어야 함                        | `"이메일을 입력하세요"` / `"이메일 주소의 형식이 올바르지 않습니다"` |
| 전화번호       | 숫자, 공백, `-`, `+`, `(`, `)` | 선택      | 입력했다면 국내 또는 국제 전화번호로 해석 가능한 유효한 번호여야 함 | `"전화번호 형식이 올바르지 않습니다"`                                |
| 문의 유형      | 드롭다운 항목의 고정 식별자    | 필수      | 기본 플레이스홀더는 선택값으로 인정하지 않음                        | `"문의 유형을 선택하세요"`                                           |
| 메시지         | Unicode 문자열                 | 필수      | 앞뒤 공백 제거 후 1~1000자                                          | `"메시지를 입력하세요"` / `"메시지는 1000자를 초과할 수 없습니다"`   |
| 연락 동의      | 체크박스 선택값 `true`         | 필수      | 체크박스를 선택해야 함                                              | `"연락처 이용에 동의해 주세요"`                                      |

## 3. 다국어 지원

한국어와 영어를 지원한다.

표시 언어는 다음 우선순위로 결정한다.

1. 사용자가 이전에 선택하고 저장한 언어
2. 사용자의 브라우저 언어
3. 기본 언어인 한국어

브라우저 언어가 한국어 또는 영어가 아니라면 한국어를 표시한다. 사용자가 선택한 언어는 다음 방문에도 적용되도록 브라우저에 저장한다.

사용자가 폼을 작성하는 과정에서 언어를 변경해도 다음 데이터는 유지한다.

- 작성 중인 폼 데이터
- 선택한 문의 유형
- 메시지 글자 수
- 현재 표시 중인 검증 오류

언어가 변경되면 기존 오류의 내용도 현재 언어에 맞게 변경하고 UI에 사용되는 모든 문자열은 번역 리소스로 관리한다.

## 4. 접근성

- 모든 입력 요소에 연결된 레이블을 제공한다
- 오류 메시지를 해당 입력 요소와 연결한다
- 오류가 있는 입력 요소의 상태를 보조 기술이 인식할 수 있게 한다
- 키보드만으로 모든 입력 요소와 버튼을 조작할 수 있게 한다
- 포커스된 요소를 시각적으로 구분할 수 있게 한다
- 오류 상태를 색상만으로 표현하지 않는다

## 5. UI 테스트 자동화

다음 항목을 우선적으로 테스트한다.

- 비허용 값을 입력하더라도 제출하기 전에는 오류가 표시되지 않는가
- 최초 제출 실패 후 값을 수정해도 다시 제출하기 전에는 재검증되지 않는가
- 빈 폼 제출 시 필수 항목에 대한 오류가 표시되는가
- 이메일을 비웠을 때와 잘못된 형식을 입력했을 때 각각 알맞은 오류가 표시되는가
- 잘못된 국내 및 국제 전화번호에 대한 제출이 거부되는가
- 전화번호를 비워도 제출할 수 있는가
- 기본 플레이스홀더 상태에서는 문의 유형 검증을 통과하지 못하는가
- 메시지 최대 길이 제한이 적용되는가
- 연락처 이용 동의가 필수로 요구되는가
- 유효한 데이터 제출 시 성공 화면이 나타나는가
- 다시 작성하기가 폼 데이터와 오류를 초기화하는가
- 언어 변경 시 UI와 오류 메시지가 변경되는가
- 언어를 변경해도 작성 중인 폼 데이터가 유지되는가
- 저장된 언어가 다음 방문에도 적용되는가
- 키보드로 드롭다운과 체크박스를 조작할 수 있는가
